# CLAUDE.md

Правила для работы над проектом Personal AI Agent.

## Язык

Всегда отвечай разработчику по-русски.

## Сложность

Минимально необходимая сложность. Не добавляй абстракции, паттерны или конфигурацию
"на будущее", если это не требуется прямо сейчас. Простое решение лучше "гибкого".

## Экономия токенов

Это ключевое требование проекта:
- не отправляй модели всю БД или всю историю диалога — используй ограниченное окно
  последних сообщений (`CONVERSATION_HISTORY_WINDOW`) + точечный recall из памяти;
- не вызывай инструменты без необходимости;
- не делай повторных web-поисков по одному и тому же запросу в рамках одного ответа;
- держи system prompt коротким;
- логируй usage input/output токенов на каждый AI-запрос;
- уважай дневной лимит токенов (`DAILY_TOKEN_LIMIT`);
- не включай extended thinking для обычных задач.

## Production и безопасность

- Никакой работы с production без явного подтверждения (деплой, миграции на реальной
  БД, изменение переменных окружения на Railway и т.п.).
- Никогда не читай и не коммить секреты (`.env`, токены, ключи). `.env` — в `.gitignore`.
- Никогда не логируй `TELEGRAM_BOT_TOKEN`, `ANTHROPIC_API_KEY`, пароли, cookies —
  см. `app/logging_setup.py` (автоматический scrub известных ключей, но не полагайся
  только на него — не передавай секреты в лог-контекст напрямую).
- Любой новый инструмент, который может задеть внешние системы или необратимые
  действия, обязан иметь `permission = PermissionLevel.CONFIRM` или `CRITICAL`
  (см. `app/tools/permissions.py`), а не `SAFE`.

## Рефакторинг

Перед крупным рефакторингом объясни, зачем он нужен, и дождись согласия — не делай
это молча по ходу другой задачи.

## Тесты

После изменений в `app/` запускай релевантные тесты:

```bash
pytest
```

Тесты не должны обращаться к настоящему Telegram или Anthropic API — используй моки
(см. `tests/test_tool_calls.py` для примера фейкового `AIProvider`).

## Архитектура (кратко)

- `app/ai/base.py` — абстракция `AIProvider`, не завязывай бизнес-логику напрямую на
  Anthropic SDK. Если нужно сменить провайдера — реализуй новый класс здесь, а не
  меняй `Coordinator` или инструменты.
- `app/ai/coordinator.py` — единственный агент сейчас. Не создавай постоянную
  multi-agent систему; временные специалисты (Researcher, Analyst, Developer, Personal
  Assistant) добавляются как вызываемые Coordinator'ом функции/классы под конкретную
  задачу, когда это реально понадобится — не заранее.
- `app/tools/` — каждый новый инструмент: явная регистрация в `registry.py`, строгая
  Pydantic-схема аргументов, явный `permission`.
